# 한글(HWP, HWPX) 문서 다루기

공모전과 정부 과제는 한글 양식을 주는 경우가 많다. SKILL.md의 말투, 문장부호, 표, 캡션, 그림 규칙은 한글 문서에도 그대로 적용한다. 이 문서는 한글에서만 생기는 일을 모았다.

## 어떤 길로 만들까

| 상황 | 길 | 쓰는 스크립트 |
|---|---|---|
| 기관이 준 한글 양식을 채움, 팀이 고치던 한글 문서를 손봄 | **HWPX로 바꿔 XML을 고친 뒤 다시 HWP로** | `hwp_convert.py`, `hwpx_replace.py` |
| 형식 자유인데 제출은 한글 파일 | **Word로 만든 뒤 한글로 바꿔 손봄** | `docx_helpers.py`, `hwp_convert.py` |
| 글자만 고침 (가운데점, 엠대시, 말투, 용어 통일) | **바꿀 말 목록으로 한꺼번에** | `lint_ko.py`, `hwpx_replace.py` |
| 수식이 많은 문서 | **한글 수식 편집기 개체로 넣음** (아래 '수식') | 한글 자동화 (pyhwpx, win32com) |

어느 길이든 마지막에는 한글로 PDF를 내보내 쪽수와 쪽 나눔을 확인한다 (`hwp_convert.py 문서.hwp 문서.pdf`, `pdf_check.py 문서.pdf`).

## 규칙 검사와 글자 고치기

```bash
python scripts/lint_ko.py 기획안.hwp                  # 한글이 없어도 .hwp, .hwpx를 바로 읽음
python scripts/hwp_convert.py 기획안.hwp 기획안.hwpx
python scripts/hwpx_replace.py 기획안.hwpx 기획안_고침.hwpx --map 바꿀말.tsv
python scripts/hwp_convert.py 기획안_고침.hwpx 기획안_고침.hwp
python scripts/hwp_convert.py 기획안_고침.hwp 기획안_고침.pdf
python scripts/lint_ko.py 기획안_고침.hwp
```

- 바꿀 말 목록(`바꿀말.tsv`)은 한 줄에 `찾을 말<TAB>바꿀 말`이다. 가운데점처럼 문맥에 따라 '와', '및', 쉼표로 다르게 바꿔야 하는 글자는 낱말째로 적는다 (`데이터·모델<TAB>데이터와 모델`).
- 글자를 늘리면 줄이 늘고, 표나 그림이 다음 쪽으로 밀려 쪽수가 바뀔 수 있다. 고친 문장 길이를 원래 길이와 비슷하게 맞추고, PDF로 쪽마다 첫 줄을 원본과 비교한다.
- 원본 파일은 덮어쓰지 않고 새 이름으로 저장한다. 사용자가 한글에서 원본을 열어 둔 채 고치고 있을 수 있다.

## 서식

| 항목 | 규칙 |
|---|---|
| 양식 우선 | 양식이 정한 글꼴, 크기, 줄 간격, 여백, 표 칸을 그대로 쓴다. 정한 것이 없으면 본문 10~11pt, 줄 간격 160%가 흔하다. |
| 양식 표 칸 안 본문 | 칸 위아래 안 여백을 3mm쯤 준다. 0.5mm면 쪽이 넘어갈 때 마지막 줄이 칸 선에 붙어 잘린 것처럼 보인다. |
| 쪽 나눔 | 표 칸 안에서는 '쪽 나눔'과 '문단 앞에서 쪽 나눔'이 먹히지 않는다. 새 쪽에서 시작해야 하는 부분(참고 문헌 등)은 표 밖 새 문단으로 뺀다. |
| 캡션 | 한글 캡션 기능(개체 선택 → 캡션 넣기)으로 번호가 자동으로 매겨지게 한다. 표는 위, 그림은 아래. `<표 1>`, `(그림 1)`의 괄호는 번호 앞뒤에 글자로 넣는다. 본문에서 표를 부를 때도 `<표 1>`로 쓴다. |
| 표 나눔 | 작은 표는 쪽에서 나뉘지 않게 하고 '글자처럼 취급'으로 둔다. 그래야 캡션과 함께 다음 쪽으로 넘어간다. 떠 있는 표(글자처럼 취급 해제)는 쪽 아래에서 넘치거나 캡션보다 앞에 놓일 수 있다. 한 쪽보다 큰 표만 '셀 단위로 나눔'과 제목 줄 반복을 쓴다. |
| 다음 문단과 함께 | 제목과 그다음 문단, 캡션과 표만 묶는다. 소개 문장까지 묶으면 큰 덩어리가 통째로 다음 쪽으로 넘어가 앞 쪽에 빈 공간이 생긴다. |
| 빈 문단 | 캡션 뒤나 표 사이의 빈 문단은 묶음을 끊는 역할을 한다. 지우지 말고 글자 크기를 3pt쯤으로 줄인다. 그림과 캡션 사이의 빈 문단은 지워야 둘이 같이 다닌다. |
| 그림 | PNG로 넣는다 (한글의 SVG 지원은 버전마다 다르다). 문서 폭 180mm라면 `svg_to_png.py --width 3600` 이상으로 만든다. |
| 문장 끝 | 문장과 글머리표 항목은 마침표로 끝낸다. 인용 번호는 마침표 앞에 둔다 (`...했음[3].`, 여러 개는 `[1], [3]`처럼 오름차순). |

## Word에서 한글로 바꿀 때 확인할 것

한글에서 .docx를 직접 열어 '다른 이름으로 저장'에서 한글 문서(.hwp)로 저장한 뒤 아래를 확인한다. 자동화(`hwp_convert.py 기획안.docx 기획안.hwp --try-docx`)는 한글 버전에 따라 안 된다. 한컴오피스 2018은 자동화로 docx를 열면 한글 대신 한워드(Hword.exe)를 띄우고 열기에 실패하며, 한워드 시작 화면이 화면에 남아 다음 자동화까지 막는다.

- 캡션 번호가 필드에서 글자로 바뀌었는지. 그림이나 표를 더 넣을 예정이면 한글 캡션 기능으로 다시 단다.
- 글머리표 기호와 들여쓰기, 표 선 굵기(굵은 검정 1.25pt, 칸 사이 0.5pt), 칸 세로 가운데 정렬.
- Word 문서에 SVG와 함께 넣은 PNG가 그림으로 들어왔는지, 흐리지 않은지.
- 글꼴이 다른 글꼴로 바뀌지 않았는지 (한글에도 같은 글꼴이 설치돼 있어야 한다).
- 쪽수. Word와 한글은 줄 나눔이 조금 달라 쪽 끝이 바뀔 수 있다.

## HWPX를 직접 고칠 때

HWPX는 zip 파일이다. 본문은 `Contents/section0.xml`, 글자 모양과 문단 모양은 `Contents/header.xml`에 있다.

- 글자는 `<hp:p>` 안 `<hp:run>` 안 `<hp:t>`에 있다. 서식이 바뀌는 곳마다 `<hp:t>`가 나뉜다.
- 고친 문단의 `<hp:linesegarray>`를 지운다. 남겨 두면 한글이 저장해 둔 줄 나눔을 그대로 써서 글자가 겹치거나 잘린다. 구조를 크게 바꿨다면 모든 문단에서 지운다 (`hwpx_replace.py --all-lineseg`).
- 새 문단은 같은 종류의 기존 `<hp:p>`를 복제해 글자만 바꾼다. `charPrIDRef`, `paraPrIDRef`는 기존 번호를 다시 쓴다.
- 새 문단 모양이 필요하면 `header.xml`의 `<hh:paraPr>`를 복제해 새 id(가장 큰 id + 1)를 주고 `<hh:paraProperties itemCnt>`를 1 늘린다. 글자 모양(`charPr`), 테두리(`borderFill`)도 같다.
- 한글은 저장할 때 쓰지 않는 서식을 지운다. 다른 문서에서 복사해 온 표는 그 표가 쓰는 `borderFill`, `charPr`, `paraPr`도 `header.xml`에 함께 넣어야 한다.
- 다시 묶을 때 zip 안 파일 순서와 압축 방식을 원본과 같게 한다 (`mimetype`이 맨 앞, 무압축). `hwpx_replace.py`가 이렇게 묶는 예시다.
- 좁은 표 칸의 긴 영어 낱말은 양쪽 정렬 때문에 글자 사이가 벌어진다 ("T r u s t e d"). 그 칸만 왼쪽 정렬 문단 모양을 쓰거나, 표에는 약어를 쓰고 풀이는 본문에 쓴다.

## 수식

- 수식은 한글 수식 편집기 개체로 넣는다. 자동화로는 `HAction.GetDefault("EquationCreate", HParameterSet.HEqEdit.HSet)` 뒤 `string`(수식 스크립트), `BaseUnit`(글자 크기)을 정하고 실행한다.
- 스크립트 주의: `{rm ...}`, `{bold ...}`는 중괄호로 감싸야 뒤 글자에 번지지 않는다. `<=`, `>=`는 ≦, ≧로 나오니 `leq`, `geq`를 쓴다. `rm total`처럼 `to`로 시작하는 낱말은 예약어로 잘리니 다른 말을 쓴다.
- 수식은 줄을 바꾸지 않는다. 가운데 수식 한 줄이 본문 폭을 넘지 않게 한다.
- HWPX의 `<hp:script>` 글자를 고치면 한글이 다시 그린다. 줄 수가 같으면 쪽 나눔도 그대로다.

## 한글 자동화가 멈출 때

| 증상 | 원인과 해결 |
|---|---|
| 연결(Dispatch)에서 멈춤 | 사용자의 한글 창에 문서가 열려 있음. 한글 문서를 모두 닫고 다시 한다. 사용자의 한글을 강제로 끄지 않는다. |
| 파일 열기나 저장에서 멈춤 | "접근 허용" 보안 창이 숨은 창 뒤에 떠 있음. 보안 모듈(FilePathCheckerModule)을 등록한다 (`hwp_convert.py --security-dll`). |
| 경로에 따라 말없이 멈춤 | 한글이 들어간 경로. 영문 경로로 복사해서 바꾼다. |
| HWP 저장 뒤 PDF 저장에서 멈추거나 RPC 오류 | 같은 세션에서 연달아 저장함. 저장 한 번마다 프로세스를 새로 띄운다 (`hwp_convert.py`는 한 번에 하나만 바꿈). |
| 다음 실행부터 계속 "서버 실행 실패" | 멈춘 숨은 Hwp.exe가 남아 있음. 내가 띄운 것(창이 없고 시작 시각이 내 실행과 같은 것)만 작업 관리자에서 끈다. |
| 한워드 시작 화면이 화면에 남아 있고, 그 뒤 자동화가 "서버 실행 실패"를 내거나 멈춤 | 자동화로 .docx를 열려다 한워드(Hword.exe)가 떠서 멈춤. Hword.exe를 끄고, docx는 한글에서 직접 열어 저장한다. |
| 대상 파일 복사나 덮어쓰기 실패 | 사용자가 그 파일을 한글에서 열어 둠. 새 이름으로 저장하고 알린다. |
